<follow_ups>
## Open architectural follow-up

The batched_embed cost-amplification fix (Task 8) only helps **txtai** because that's the one engine routing through `batched_embed`. The other four engines hand their embedder objects to library code (haystack's `OpenAIDocumentEmbedder`, langchain's `OpenAIEmbeddings`, llamaindex's `OpenAILikeEmbedding`, chromadb's `OpenAIEmbeddingFunction`) — each library does its own internal batching with no shared cache.

To extend the same resumability to those engines, every engine's embedder seam would have to be routed through a single shared callable. Candidate skill to run: `/improve-codebase-architecture` against `mcp_servers/rag_pill/engines/` looking for the "5 embedder seams → 1 embedder seam" deepening opportunity.

Not blocking — txtai is the engine that surfaced the 428KB-doc bug. Other engines may have similar latent behavior on very large docs but no production report yet.
</follow_ups>
