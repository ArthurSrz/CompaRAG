<objective>
Install a Claude Code PostToolUse hook that runs a full-flow synthetic test of the production CompaRAG tool-arena UI (https://comparag.vercel.app/tool-arena) after deployment-class commands. The test exercises the upload → compare → vote (3★/3★) → reveal flow via browser-harness against production, classifies failures as hard regressions (DOM element missing → exit 2) or transients (timeout/5xx → exit 0 + warning), and appends every event as a comment on a single rolling GitHub issue (label `synthetic-monitor`) on `ArthurSrz/CompaRAG`.

Purpose: Prevent silent loss of UI features (e.g. the 5-star `ToolPreferencesPanel`) by detecting regressions within seconds of a production deploy, without blocking development on transient infrastructure flakes.

Output:
- Stable `data-testid` ancres on 5 critical UI elements (rating panels, submit, result cards, reveal)
- `scripts/synthetic_monitor.py` — self-contained browser-harness script
- `scripts/synthetic_report.sh` — GitHub issue append helper
- `scripts/fixtures/synthetic_input.txt` — fixed test corpus
- `.claude/hooks/comparag-monitor.sh` — Bash regex matcher + background launcher
- `.claude/settings.json` — PostToolUse hook registration

Non-goals (explicitly excluded by Q&A):
- No retry / backoff logic (Q5)
- No backend filtering of synthetic votes (Q4 — pollution accepted)
- No Playwright integration (Q1)
- No local dev URL coverage (Q1 — prod only)
- No per-incident GitHub issues — single rolling issue only (Q7)
</objective>

  <name>Task 2: Write the synthetic monitor script</name>
  <files>
    scripts/synthetic_monitor.py
    scripts/fixtures/synthetic_input.txt
  </files>
  <action>
    Create `scripts/fixtures/synthetic_input.txt`: ~200 words of stable, neutral text (Lorem-ipsum-style or a fixed paragraph about RAG). Must not contain dates, names, or anything that would change the LLM output meaningfully across runs.

    Create `scripts/synthetic_monitor.py` — a self-contained script that browser-harness will exec. It MUST follow the browser-harness conventions from ~/Developer/browser-harness/SKILL.md:
    - Use `new_tab(url)` for the first navigation (NOT `goto_url`)
    - Pre-imported helpers: `new_tab`, `wait_for_load`, `capture_screenshot`, `click_at_xy`, `js`, `page_info`
    - No `import` of those helpers
    - On any unexpected exit, write a JSON event file to `$SYNTHETIC_EVENT_FILE` (defaulted to `/tmp/comparag_synthetic_event.json`)

    Script flow:
    1. `new_tab("https://comparag.vercel.app/tool-arena")` then `wait_for_load()`
    2. **Hard regression check (early)**: assert `js("document.querySelector('[data-testid=tool-arena-submit]') !== null")` — if false, exit 2 with reason `missing-element:tool-arena-submit`.
    3. Upload `scripts/fixtures/synthetic_input.txt` via the file input found by `[data-testid=tool-arena-file-input]` (use CDP `Input.dispatchKeyEvent` or DOM `.files` assignment via `js(...)`).
    4. Type a fixed goal into `[data-testid=tool-arena-goal]`: "Synthetic monitor probe — extract the main idea."
    5. Click `[data-testid=tool-arena-submit]` (use coordinates from `getBoundingClientRect()` then `click_at_xy`).
    6. Wait up to 90s for `js("document.querySelectorAll('[data-testid^=tool-result-]').length === 2")`. Poll every 1s. If timeout: classify as transient, exit 0 with stderr warning `transient:result-timeout`.
    7. **Hard regression check (rating)**: assert both `[data-testid=tool-rating-a]` and `[data-testid=tool-rating-b]` are present. If either missing, exit 2 with reason `missing-element:tool-rating-{side}`. THIS IS THE PRIMARY GUARD AGAINST THE LOSS THAT MOTIVATED THIS PHASE.
    8. Click `[data-testid=tool-rating-star-a-3]` and `[data-testid=tool-rating-star-b-3]` (3★/3★ neutral vote per Q9a).
    9. Submit the vote (find vote submit button — likely needs another `data-testid` if not added in Task 1; if so, fall back to `button[type=submit]` within the vote form).
    10. Wait up to 30s for `[data-testid=tool-reveal-button]` to be visible. If timeout: transient, exit 0.
    11. Click `[data-testid=tool-reveal-button]`.
    12. Assert `[data-testid=tool-reveal-content]` becomes visible within 10s. If not: hard regression `missing-element:tool-reveal-content`, exit 2.
    13. `capture_screenshot("/tmp/comparag_synthetic_last.png")` — last frame for debugging.
    14. Exit 0 silent (success).

    Failure classification:
    - `AssertionError` on a `[data-testid=...]` lookup → hard regression → exit 2
    - HTTP 5xx detected via `read_network_requests` → transient → exit 0 + stderr
    - Any timeout in steps 6/10/12 → transient → exit 0 + stderr (EXCEPT step 12 which is hard, since the button was already clicked)
    - Any other exception → transient (conservative) → exit 0 + stderr

    Always write a JSON event file before exiting (success or failure):
    ```json
    {
      "timestamp": "<ISO8601>",
      "url": "https://comparag.vercel.app/tool-arena",
      "status": "ok" | "regression" | "transient",
      "reason": "<short slug>" | null,
      "duration_seconds": <float>,
      "screenshot_path": "/tmp/comparag_synthetic_last.png" | null,
      "trigger_command": "<from $SYNTHETIC_TRIGGER_CMD env var>"
    }
    ```
  </action>

  <name>Task 3: Write the GitHub issue append helper</name>
  <files>
    scripts/synthetic_report.sh
  </files>
  <action>
    Create `scripts/synthetic_report.sh` — bash script that reads the JSON event file from `$SYNTHETIC_EVENT_FILE` (default `/tmp/comparag_synthetic_event.json`) and appends a comment to the single rolling issue.

    Logic:
    1. If the event file does not exist or is empty → exit 0 silent (nothing to report).
    2. If `status=ok` AND env var `SYNTHETIC_REPORT_OK=0` (default 0) → exit 0 silent (do not spam the issue with green runs).
    3. Find the rolling issue: `gh issue list --label synthetic-monitor --state open --json number -q '.[0].number'`. If empty, create it: `gh issue create --title "Synthetic monitor — CompaRAG (rolling log)" --label synthetic-monitor --body "Append-only log of synthetic regression events. Each comment = one run. Closing this issue stops new comments and forces re-creation on next event."`. Pin it: `gh issue pin <num>`.
    4. Build the comment body from the JSON: status emoji (✅/🔴/🟡), timestamp, trigger command, reason, screenshot path (local only — not uploaded; user can fetch if needed), duration.
    5. Post: `gh issue comment <num> --body-file <comment.md>`.
    6. If `gh` is missing or unauthenticated → write a warning to stderr but exit 0 (do not break the host Bash tool call).

    Hard requirements:
    - Use `set -u` but NOT `set -e` (we never want this script to fail and break the user's terminal).
    - All `gh` calls wrapped in `|| true` with a stderr message on failure.
    - Comment body must include the trigger command verbatim so the user can correlate with their terminal history.
  </action>

    1. Create `.claude/hooks/comparag-monitor.sh`:
       - Read JSON from stdin via `jq -r '.tool_input.command // empty'` (or fallback to python if jq absent)
       - Match command against regex: `git push.*\b(main|develop)\b|vercel.*--prod|railway up|make docker-app-up|gh pr merge`
       - If no match → exit 0 immediately (fast path; ~20ms overhead per Bash call)
       - If match: launch the synthetic monitor in **background**:
         ```
         (
           export SYNTHETIC_TRIGGER_CMD="$cmd"
           export SYNTHETIC_EVENT_FILE="/tmp/comparag_synthetic_event_$$.json"
           browser-harness -c "$(cat scripts/synthetic_monitor.py)" \
             >> ~/.claude/logs/comparag-monitor.log 2>&1
           bash scripts/synthetic_report.sh \
             >> ~/.claude/logs/comparag-monitor.log 2>&1
         ) &
         disown
         ```
       - Exit 0 (the host Bash command must not be blocked — the monitor reports out-of-band via the GitHub issue)

    2. Update `.claude/settings.json` to register the hook on PostToolUse with matcher `Bash`. Preserve any existing hooks/settings (read first, merge — DO NOT overwrite).

    Example settings stanza:
    ```json
    {
      "hooks": {
        "PostToolUse": [
          {
            "matcher": "Bash",
            "hooks": [
              {
                "type": "command",
                "command": ".claude/hooks/comparag-monitor.sh"
              }
            ]
          }
        ]
      }
    }
    ```

    3. Make `.claude/hooks/comparag-monitor.sh` executable (`chmod +x`).

    4. Add a memory entry at `~/.claude/projects/.../memory/feedback_synthetic_monitor.md` and link from MEMORY.md, documenting:

       - Where logs go (`~/.claude/logs/comparag-monitor.log`)
       - How to disable: comment out the PostToolUse stanza in `.claude/settings.json`, OR set env var `COMPARAG_SYNTHETIC_DISABLED=1` (the hook script must respect this)

    5. Add the env-var disable check at the top of `comparag-monitor.sh`: `[ -n "${COMPARAG_SYNTHETIC_DISABLED:-}" ] && exit 0`.
